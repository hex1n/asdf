# 工作循环（任意项目通用）

默认轻量：能直接做的直接做。微小改动（单文件、无数据/接口影响）不开环，
一句"现状 → 期望"即可。升档只有三个入口：用户显式要求、多机制未收敛、
改动不可逆/高风险（数据、接口、权限、资金）。品味类交付（判据写不出可
执行形式）走 judgment 环：先预注册 rubric 再动笔，fresh-context 独立评审，
终态是人的验收；连 rubric 都写不出的探索性工作不上环，直接做，不硬造判据。

## 机器跑循环（任务是一等公民，说一次）

- **唯一分叉是判据溯源**：given（拍板方案自带检查）/ recovered（先复现失败，
  红从世界挣来）/ absent（keep-green 只读核验，绿是稳态，只由显式动词收口）。
  之后同壳。缺判据先索要再动手。
- **开任务**：`taskloop open` —— goal + criterion（出生即红、幂等可复跑、机器
  可执行：测试命令、SQL 断言、预期响应）+ **alignment**（绿为什么⇒目标、不
  覆盖什么；诚实答案若是"绿证明不了什么"，先加强判据再开）+ **envelope**
  （目标仓库/工作目录 + 将触碰的文件/表/接口）。envelope 是写边界，读与验证
  永远自由。真判据被环境挡死 → `suspend needs_input` 或降级为 `.taskloop/`
  适配器（引擎记 provenance 随账走），不以对将改文件的文本断言硬凑绿。
- **推进**：改 → 判据闸门现场跑判据 → 修；红的反馈尾就是下一轮输入，轮间
  不问人。判据本身错了 → `amend` 带理由重指纹，不悄悄改检查文件。判据弱的
  工作（重构/迁移类）收口前补独立评审：fresh-context 起步、second-model 更好，
  记 provenance，不当闸门。碰 envelope 之外 → 停下确认，不顺手扩界。
- **收口只有一扇门是成功**：判据绿收 `done`——绿只从新鲜跑出的判据来，没有
  claim-based 成功。人为关闭仅 `not-needed`（带证据）与 `abandon`（带理由）。
  **挂起（`suspend`：`stuck`/`out_of_budget`/`needs_input`）不是关闭**：任务
  保持 open，预算挂任务上、续跑不回填；机器自记已改文件与死路清单，人只补
  剩余判据/当前失败/下一步三行。
- **账**：开与收各落结局账一行（出树只追加，供元循环）；开而不收，账上可见。

## 人持有四个动词

- **拍板**：定方案与预算。落地指令一出即执行许可，不自设新的收敛或规划
  关卡；只为缺判据、envelope 外触碰、新硬阻塞三种情况停下。用户说"先给
  方案/先不 coding/先分析"时只产出分析，写文件/写库等明确落地指令。
- **代行**：机器够不着的外部动作（部署、凭证、无法自起的环境）由人执行，
  agent 触发并给出可直接照做的精确指令。
- **验收**：终局由人拍。品味类交付的终态动词就是验收。
- **转向**：中途改向/叫停/补判断是**一等输入**，立即吸收、复述更新后的
  envelope 再继续；不视为打断，也不自动重开收敛。

驱动器与停机门分离：驱动器（人、/goal、/loop、定时任务）负责"再来一回合"，
taskloop 只裁"这一回合能不能收"。循环开口要人当时钟/判停器/守卫/记忆，
是缺陷（记入元层），不是这四个动词。

## 硬约束

- 要声明"完成/已验证" → 必须指向本会话的真实工具输出（命令结果、diff/status、
  SQL 断言）；工具失败或未运行 → 如实报告失败。宁可报红，不许假绿。
- 要执行删除/清空/重置或 git 操作（add/commit/push/reset/restore/checkout/clean）
  → 仅在用户明确要求且 envelope 授权（`--git-allowed`/`--git-reason`）后进行；
  被要求提交时沿用仓库历史作者身份。
- `.taskloop/task.json` 与结局账只经 `taskloop` CLI 动词变更，不手写。
- 循环机制细节（任务状态、envelope 强制、判据闸门、轮次/写/墙钟/token 预算、
  判据输入指纹、自动挂起）→ 由 `taskloop` CLI 与其 PreToolUse/Stop hook 承载，
  本卡不重复。

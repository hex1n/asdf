# Loop v2:task-first 循环工程(设计存档 + 分波落地计划)

白纸重设计,经一轮自我证伪修订(v2)。本文是设计存档与落地切分;
第一波实现随本文同分支落地。

> 作者准则降级记录:`writing-great-skills`(仓外用户级 skill)在本环境
> 不可加载;新 skill 按其列出的准则直接编写(可预测性、信息层级、

## 设计总原则

**不给控制器编程,给控制器造马具。** LLM 是换不掉也改不了内部的控制器;
工程量全部投在确定性部件上:设定值、反馈、监理、记忆、经济、改进回路。
每个机制必须对应一个**具名失效模式**,否则不建。

## 核心对象:Task,不是 Loop

- 一等公民是**任务档案**:goal / criterion(出生即红、幂等、防篡改可见)/
  alignment / envelope / **预算挂任务上** / episodes[]。
- episode(一次连续运行)挂在 task 之下;会话死亡只是 episode 结束。
- 两层终态:episode 出场(green / stuck / moving-out-of-budget /
  needs-input)与任务终态(done / not-needed / abandoned+reason)分层;
  挂起是常态中间态,续跑是常规操作。
- 反洗预算定位为**可见性设计**,不是结构保证(协作模型下一切反洗白
  都只是可见性;由人裁决)。

## 四个子系统(各自杀死的失效模式)

1. **设定值工场**:判据五性质(可执行/出生红/幂等/便宜/防篡改可见)+
   **适配器插座**(接口契约把三个已知陷阱编码为要求:必过集显式、
   新鲜度指纹、退出码语义 0/1/2)+ 插头按失败证据逐个生长。
   进度标量降级为**只给人看的遥测**,不输入任何机器决策。
   ——杀死:橡皮图章、空洞通过、陈旧绿、改测试凑绿。
2. **监理**:准入(无红判据不开写)、界限(envelope + 两侧预算成对)、
   裁决(判据裁停 + 签名史分型)、**挂起时代写快照的机器半边**
   (已改文件清单由监理从自己的观察生成,agent 只补剩余/失败/下一步
   三行判断)。fail-open,担保边界显式。
   ——杀死:提前误停、范围漂移、奔逸、快照靠自觉。
3. **记忆**:任务账(仓内私有)+ 结局账(出树只追加,runtime 只写不读)+
   上下文经济纪律(episode 便宜,鼓励快照重开胜过长会话硬熬)。
   ——杀死:跨会话失忆、遥测变运行时依赖。
4. **元层**:装机挂表(安装时询问、默认勾选),指标回答一个问题——
   "人还在哪里干机器的活";收割闸 + 证据环;规则默认落进机器,
   prose 是最后选择。——杀死:元循环永远下个月、拍脑袋立规。

## 控制器程序(薄)与人机接口

- **工作环**:唯一分叉是判据溯源(given / recovered / absent),之后同壳。
- **决策环**:证伪反馈的另一物种(现 converge)。
- **判断环**(新物种,覆盖不可机器判据的品味工作):先于动笔的
  **预注册 rubric** 充当 red-at-init 的对应物;fresh-context 独立评审充当
  幂等裁决;终态永远是人的验收。rubric 都写不出的探索性工作不上环。
- **元环**:绑定月度定时器的程序。
- 人持有**四个动词**:拍板、代行、验收、**转向**(中途改向是一等输入,
  不是打断)。缺陷的定义:只有**循环开口要人**当时钟/判停器/守卫/记忆
  才算,自动成为元层输入。

## 不做

多代理编排平台、防篡改签名、进度驱动的预算自动续期、部署自动化、
为不可预注册的探索性工作硬造判据。

## 落地切分

### 第一波(非破坏,随本文落地)

| 项 | 落点 | 杀死的失效模式 |
|---|---|---|
| 机器半边快照 | 闸门/CLI 维护 `evidence.touched_files`(监理观察所得),释放/收口/续跑时机器自报已改文件 | 快照全靠 agent 自觉、漏报已改文件 |
| 适配器插座 | `skills/loop-core/ADAPTERS.md` 接口契约;`e2e-report-check.mjs` 即种子实现 | 手写判据的三类已知陷阱 |
| `meta-loop` skill | 元循环获得可调用入口,绑定既有 cron 约定 | 元循环流程散在 prose、无入口 |
| `judgment-loop` skill | 预注册 rubric + fresh-context 评审的品味工作环 | 不可验证工作要么硬造判据要么裸奔 |
| 第四动词"转向" | 契约卡各加一行 + parity token | 合法转向被流程当成违规;循环反过来责怪用户打断 |
| 任务重叠软提示 | init 无血缘命中时,对结局账做只读扫描,同仓近期非成功且判据不同 → 一行提示(读不到即静默,保持非承载) | 换名洗预算完全不可见 |

### 第二波(破坏性;逐项过 AGENTS.md redesign gate 后才动)

预注册判别探针(先于任何实现固定):

1. **task-first schema v3**(episode 挂任务下、预算上移)——探针:第一波
   血缘/快照机制运行 ≥1 个月后,`resume_count>0` 的任务里出现"预算按
   契约实例计导致的真实误判"(机器认为新任务、人认为同任务)≥2 例。
2. **两层终态 taxonomy**——探针:结局账里 blocked/stalled/exhausted 的
   使用出现语义混淆(同种情形被记成不同终态)≥2 例。
3. **land/fixloop/loop 合并为 workloop**——探针:语料中出现两 skill
   路由混淆或规则漂移(parity 测试失守或人工纠正)≥2 例。
   预期:此项大概率被证伪毙掉,保持现状即结论。

任一探针不触发,对应改动不做——elegance 不是证据。

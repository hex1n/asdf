## 支撑分析

### 根问题重构

你提出的是解法，不是问题。五问法拆解：

```
陈述: 加一个自动坏数据检测+自动重放模块
为什么？ -> 上游偶尔发坏文件，导致报表错误
为什么这算问题？ -> 现在靠人工按 runbook 回填，占用1-2小时
为什么人工回填是要解决的问题？ -> 直觉上"手动的事应该自动化"
但实际发生了什么？ -> 频率低(2-3次/年)、成本低(1-2小时/次)、2年零二次事故——现有流程没有被证明失败
```

真正的根问题不是"如何设计检测+重放"，而是：**是否值得为一个低频、低成本、已被验证安全的人工流程，投入5-8人日+永久维护去自动化**——而你上下文里唯一明确的运营风险（唯一维护者）恰恰不需要靠自动化解决，脚本化/文档化就能大幅缓解。

**量化**：现状年成本 ≈ 2-3次 × 1-2小时 = 每年2-6人时。原方案一次性投入5-8人日 = 40-64人时，还不含此后每年1-2次的检测规则维护。即使忽略维护成本，单纯回本也需要 40-64 ÷ 4(中位数年节省) ≈ **10-16年**——在有其他积压排队、无合规强制要求的前提下，这个投资回收期站不住脚。

但见下文"S-tdd-2 潜伏 bug":oracle 覆盖之外仍有真实缺陷,满分≠无缺陷。

### 2. 盲评综合排名(两任务、每任务两名独立评审,四名全部一致)

| 任务 | 排名(1=最好) |
|---|---|
| S | ctl-1 > ctl-2 > tdd-1 > tdd-2 |
| M | ctl-1 > ctl-2 > tdd-1 > tdd-2 |

对照臂平均名次 1.5,TDD 臂平均名次 3.5,四份独立排名零分歧。
分维度看有细节:**设计**维度 TDD 臂不吃亏(S 评审 1 把 S-tdd-1 的实现评为
"最干净自然";两名 M 评审都称 M-tdd-1 领域模型最干净)——输在**测试套件**:

- M-tdd-2:幂等重放测试没先改变状态,区分不出"原始快照"与"现算值"。
- S-tdd-2:见下。

### 3. S-tdd-2 潜伏 bug(本实验最重要的单点发现)

完整证据链:

1. 规格 Example 1 有一处**勘误**(示意性浮点尾数 `1.0000000000000002`,
   实际按规则 4 公式算恰好是 1)——无意为之,成了天然陷阱。
2. 4 份实现里 3 份(两份对照 + S-tdd-1)把它当示意值,按公式实现;
   **唯独 S-tdd-2 把勘误当权威**,专门改成逐单位累加循环去逐位复现该浮点,
   并在注释里说明这么做是为了匹配 Example 1。
3. 它自己的测试断言 `amount === 1.0000000000000002`,**把错误行为钉死**——
   任何按规则 4 公式的正确实现反而过不了它的测试。
4. 后果是真 bug:小数单位被 `ceil(units)` 次迭代多收费。执行复核:
   `2.5 单位 × 100 × 1.5%` 应收 **3.75**,S-tdd-2 收 **4.5**;其余三份全对。
5. 该 bug 穿过了两层"绿灯":自测 20/20 全绿,留出 oracle 14/14 全绿
   (oracle 全部用整数单位,是覆盖盲区)。**只有盲评审读代码抓到**,
   执行复核坐实。

这是文章 "theater" 论点的完整活标本:自己出题(把勘误写进测试)→ 自己考试
(实现迁就测试)→ 自己宣布满分(20/20)。且值得注意:tdd skill 要求
"期望值必须来自独立事实源(如 spec 的 worked example)"——正是这条规则把
勘误抬成了权威。规格里的示例是**规格的一部分,不是独立事实源**。

## 结论(假设级,非定论)

1. **H0 成立方向**:规定性 agent-loop TDD 在正确性上无增益(饱和),
   盲评综合质量四评审一致更低,成本高 ~45-150%。与 Böckeler 一致,
   且本实验的盲评分歧比她的更小(她是"略高",这里是零分歧的 1.5 vs 3.5)。
2. **TDD 臂的失分点不是设计而是测试覆盖**:red→green 垂直切片产出的
   精选小套件(≈19 条)在具名规格规则上留洞;对照臂"实现后穷举"套件
   (≈72 条)反而是更强的行为钉死。这与她的"增量锁死设计"假设不同——
   本实验设计不吃亏,吃亏的是**切片式测试生成的覆盖面**。
3. **"worked example 当独立事实源"是可复现的失败模式**:规格示例的一处
   勘误被 TDD 臂的一次运行奉为权威并用测试钉死,产生穿透两层绿灯的真 bug。
4. **单层外部验证不够**:留出 oracle 放行了带 bug 的实现(覆盖盲区),
   盲评审读代码抓到,执行复核坐实。信任根需要异质多层
   (oracle + review + 执行探针),任何单层都有自己的盲区。

## 对 `tdd` skill(~/.agents/skills/tdd,第三方个人 skill)的建议

- **不建议**继续往 agent 内部循环加检查点(如 red 人审门)来"修"它——
  本实验方向上循环本身对 agent 无增益,修饰仪式不如换协议。
- 若保留,建议重定位为文章的模式 1/2:人写/人审可执行规格,agent 快速实现,
  外部多层验证;并明确"规格中的 worked example 是说明性的,除非显式钉死,
  不得作为逐位权威"。
- 对本仓库:维持现有架构方向(规格与验证分离、独立证伪、外部信任根),
  本实验为其提供了一次受控证据。

# Meta-loop (file-state)

The meta-loop is the offline maintenance loop that keeps the skills healthy:
**analyze sessions → find skill failure modes → run one evidence round per
candidate → decide with the AGENTS.md gates.** It is long and spans sessions and
months, so it does **not** live in one chat's context window. State lives in
files + git, and each iteration runs in a **fresh context** (the Ralph pattern):
progress accumulates in the backlog and round notes, not in a growing transcript.

## State layout

| Path | Tracked? | Holds |
|---|---|---|
| `docs/research/*.txt` (loop-health, corrections, first_prompts) | gitignored | Private session corpus — real business identifiers; regenerated by `analyze-sessions.py`, never published. |
| `docs/meta-loop/backlog.jsonl` | tracked | Sanitized improvement candidates + their decision status. The durable "what's next". |
| `docs/meta-loop/rounds/` | tracked | One AGENTS.md round note per resolved candidate. |

Only **neutral, reviewable** candidates enter the tracked backlog — sanitize
failure-mode wording before `enqueue` (Generalization Gate: no source-project
identifiers). The raw corpus stays gitignored.

## One iteration (fresh context each time)

The driver reads the backlog to find its single unit of work, does exactly that
unit, records the outcome, then exits. The runtime re-feeds a fresh context.

```text
1. node ~/bin/meta-loop.mjs next --repo <asdf-repo>
   - Prints the single active unit: any in_progress candidate (keep working it;
     a stale one means a prior round crashed), else the oldest pending, which it
     claims -> in_progress. One slot: an active claim blocks a new one. Or "none".
   - "none": run the corpus + drift step (below), enqueue any new candidates
     with sanitized wording, then STOP. The next iteration picks them up.
2. For the claimed candidate, run ONE AGENTS.md evidence round:
   baseline -> name the failure mode -> narrowest edit -> independent
   adversarial-falsification subagent (fresh context) -> decide with the hard
   gates + two-axis rule. Do not self-grade in the same context that wrote it.
3. Write the round note to docs/meta-loop/rounds/<id>-<slug>.md (AGENTS.md
   compact format), then:
   node ~/bin/meta-loop.mjs resolve --id <id> \
     --decision accept|reject|continue --note docs/meta-loop/rounds/<id>-<slug>.md
   (`continue` keeps it in_progress for another round; accept/reject is terminal.)
4. STOP. Do not start a second candidate in the same context.
```

Corpus + drift step (only when `next` says "none"):

```text
python docs/research/2026-07-02-analyze-sessions.py --out <scratch-dir>
# diff <scratch-dir>/loop-health.txt against the recorded baseline (playbook §5).
# For each metric that regressed or each repeated correction, enqueue a
# sanitized candidate:
node ~/bin/meta-loop.mjs enqueue --repo <asdf-repo> \
  --skill <skill> --failure "<neutral failure mode>" --evidence "<sanitized pointer>"
```

## Stop conditions and budget (Ralph guardrails)

- **Per iteration**: exactly one candidate, one round, then exit. Never batch.
- **Terminal**: `next` returns "none" **and** a fresh corpus+drift run enqueues
  nothing new — the loop is drained; stop re-feeding.
- **Budget**: the re-feed mechanism sets a wall-clock and/or iteration cap; on
  cap, stop and hand back, do not silently re-run. A crashed round is safe:
  its candidate stays `in_progress` and `next` re-offers it after
  `STALE_CLAIM_SECONDS` so the following fresh context resumes it.

## Re-feed mechanisms (per runtime)

The driver above is runtime-neutral. Wire the re-feed to whichever runtime runs
the schedule (both cap wall-clock/iterations and escalate on cap, not retry):

- **Claude Code**: the official `ralph-loop` plugin (`/plugin install
  ralph-loop@claude-plugins-official`) drives fresh-context iterations of the
  driver prompt until a completion promise; or a system scheduler runs
  `claude -p "<driver prompt>"` on a cadence.
- **Codex**: a standalone `automation` runs `codex exec "<driver prompt>"` on a
  cadence.

`agent-doctor.py` reports backlog health (pending/in_progress counts, stale
claims, loop-health.txt age) so a missed or stuck month is visible.
